# Laboratory Work #3: Synchronization of Threads

## 📝 Описание
Проект реализует задачу синхронизации потоков в рамках одного процесса на языке C++.
Реализована модель взаимодействия **"Главный поток - Рабочие потоки"** (Main-Marker).

**Задача:**
Потоки `Marker` конкурируют за доступ к общему массиву целых чисел.
1. Поток захватывает доступ к массиву.
2. Генерирует случайный индекс.
3. Если ячейка равна `0`, поток помечает её своим `ID`.
4. Если ячейка занята, поток сигнализирует главному потоку о невозможности продолжения.
5. Главный поток (`Main`) управляет жизненным циклом маркеров: останавливает их работу или дает сигнал продолжить.

## 🛠 Технологии
*   **Язык:** C++
*   **API:** Windows API (Threads, Critical Sections, Events)
*   **Стандарт C++:** Использованы элементы C++11 (`<thread>`, `<chrono>`) для управления задержками.
*   **Тесты:** Doctest (Unit-тестирование логики).

## ⚙️ Ключевые особенности
*   **Синхронизация данных:** Использована **Критическая секция (`CRITICAL_SECTION`)** для обеспечения атомарности операций записи в массив.
*   **Управление потоками:** Реализовано через **События (`HANDLE`, CreateEvent)**:
    *   `start_event` — синхронный старт всех потоков.
    *   `cannot_continue_event` — сигнал остановки маркера.
    *   `stop_event` / `continue_event` — управляющие сигналы от Main.
*   **Предотвращение Deadlock:** Реализован механизм освобождения критической секции перед уходом потока в режим ожидания.

## 🧪 Тестирование
Для проверки корректности работы структур данных и логики очистки памяти написаны Unit-тесты с использованием фреймворка **Doctest**.
Тесты проверяют:
*   Инициализацию структур данных.
*   Логику пометки ячеек массива.
*   Логику очистки массива при удалении потока.
